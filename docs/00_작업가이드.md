# 00. 추가 개발 작업 가이드

우수작품경진대회 출품(9/15 제출)을 위한 **추가 개발** 문서 모음이다.
프로젝트 자체 설명은 루트의 `README.md`를 본다. 이 폴더는 추가 개발 작업용이다.

Claude Code는 작업 시작 전 이 문서와 해당 작업 문서를 먼저 읽는다.

## 문서 목록

| 문서 | 내용 | 언제 읽나 |
|---|---|---|
| `01_개발계획.md` | 목표, 일정, 작업 원칙 | 모든 작업 시작 전 |
| `02_알려진이슈.md` | 코드에서 확인된 문제와 근거 위치 | 인프라·메트릭·대시보드 작업 전 |
| `03_대시보드명세.md` | 모니터링 대시보드 Phase별 작업과 완료 기준 | 대시보드 작업 시 |

## 작업 규칙

1. 작업 브랜치에서만 작업한다. main 직접 커밋 금지.
2. 한 번에 한 Phase만 진행한다.
3. 측정하지 않은 수치를 코드·UI·문서 어디에도 넣지 않는다.
4. 문서와 코드가 다르면 **코드가 기준**이다. 차이를 보고하고 문서를 고친다.

## Phase 하나를 진행하는 순서

1. **계획**: Claude Code를 Plan 모드로 두고 해당 Phase 계획을 요청한다. 코드는 수정되지 않는다.
2. **검토**: 계획이 명세(`03_대시보드명세.md`)와 맞는지, 건드리면 안 되는 파일을 건드리지 않는지 확인한다.
3. **실행**: 계획을 승인하고 구현한다. 파일 수정마다 변경 내용을 확인한다.
4. **검증**: 해당 Phase의 완료 기준 체크리스트를 **사람이 직접** 확인한다. `pytest tests/` 포함.
5. **커밋**: 체크리스트가 전부 통과하면 커밋한다. 실패하면 고치거나 `git restore .`로 되돌린다.
6. 다음 Phase로 넘어갈 때 Claude Code에서 `/clear`로 대화를 비우고 1번부터 반복한다.
